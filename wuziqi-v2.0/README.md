# 五子棋 · 局域网联机

一个**纯前端、零依赖、无需任何后端服务器**的双人五子棋对战游戏。
两台设备连同一个 Wi-Fi，通过「邀请码 / 回传码」手动交换信令，即可用浏览器内置的
WebRTC 建立点对点直连，数据不经过任何第三方服务器。

---

## 快速开始

**直接双击 `index.html` 用浏览器打开即可**，不需要安装任何东西，也不需要启动本地服务器。

> 推荐使用 Chrome 或 Edge（新版 Firefox / Safari 亦可）。

### 三种玩法

| 模式 | 说明 | 需要几台设备 |
|---|---|---|
| **本机双人** | 同一台设备上轮流落子，无需联网 | 1 台 |
| **创建房间** | 你当房主，执黑先行，生成邀请码发给好友 | 2 台 |
| **加入房间** | 你收到邀请码，执白后手 | 2 台 |

### 联机流程（4 步）

```
房主                                    好友
─────────────────────────────────────────────────────
1. 创建房间 → 生成邀请码
2. 复制邀请码 ─────────────────────────▶ 3. 加入房间 → 粘贴邀请码
                                              ↓
                                        4. 生成回传码
5. 粘贴回传码 ◀──────────────────────── 6. 复制回传码
   → 确认连接
              ✓ 双方自动进入棋盘，黑方先行
```

页面内每个步骤都有编号提示条和说明文字，首页的「操作教程」里还有完整图文版和常见问题。

## 功能一览

**棋局**
- 15 × 15 标准棋盘，星位、坐标标注（可开关）
- 横 / 竖 / 斜任意方向先连成五子者胜，支持和棋判定
- 长连（六子及以上）自动截取最靠落子点的五子用于高亮
- 落子悬停预览、最后一手标记、获胜连线高亮
- 高清屏适配（devicePixelRatio）、窗口缩放自适应

**联机**
- WebRTC DataChannel 点对点直连，无服务器、无中继
- 邀请码使用 `deflate-raw` 压缩 + URL 安全 Base64，文本长度约为原始 SDP 的 1/4
- 容错解析：首尾空白、换行、缺少前缀、被聊天软件换行截断均可识别
- 断线检测、连接状态实时指示
- 全量棋局同步兜底（任何一端发现不同步可自动拉齐）

**对局交互**
- 重新开始 / 悔棋 / 认输，均为「请求 → 对方同意」的双向确认机制
- **聊天面板**（微信风格）：气泡对话、头像、时间分隔、「对方正在输入…」提示；自己发的靠右、对方发的靠左
- 对局记录面板与聊天完全分离，只记录落子和系统事件
- Web Audio 实时合成音效，零音频文件；可开关
- 明 / 暗双主题，跟随系统偏好，可手动切换

## 技术要点

### 为什么不需要服务器？
WebRTC 建立连接前需要交换 SDP（会话描述信息）。常规做法是搭一台信令服务器，
本项目的做法是：把这串信息压缩成文本，让你通过微信 / QQ 自己发给对方。
信令交换由聊天软件代劳，服务器就省掉了。

### 关键修复：制胜一子不同步
参考的原项目在落子直接获胜时，只发送了 `{ type: 'game_end', winner }`，
**没有带上最后落子的坐标**，导致接收方棋盘缺少制胜的那颗棋子、也画不出获胜连线。

本项目的做法是从根上避免这个问题：**无论这一步是否分出胜负，都如实把坐标发出去，
由双方各自在本地用同一套规则算出结果**。由于输入相同、算法相同，结果必然一致。

### 点击不重复触发
原项目同时绑定了 `click` 和 `touchend`，移动端可能一次点击落两子。
本项目统一使用 Pointer Events，并在 `pointerup` 时校验位移（< 12px）与时长（< 800ms），
既避免重复触发，也不会把「拖动滚动」误判成落子。

### 点击坐标不错位
`renderer.pointFromEvent()` 会用 `逻辑尺寸 / 显示尺寸` 的比例校正坐标，
即使棋盘被 CSS 缩放，落点也不会偏移。

### 局域网为什么可以不要 STUN？
同一局域网内的两台设备可以通过 host candidate 直接互通，不需要 STUN 服务器。
默认 `ICE_SERVERS` 为空数组，ICE 收集瞬间完成，建连最快。

## 自定义配置

编辑 `js/config.js`：

```js
GM.CONFIG = {
  BOARD_SIZE: 15,        // 棋盘规格，改成 19 即为 19 路
  WIN_COUNT: 5,          // 连成几子获胜
  ICE_SERVERS: [],       // 跨网络使用时填入 STUN / TURN
  CHAT_MAX_LENGTH: 60,   // 单条消息最大长度
  ...
};
```

**需要跨网络（不在同一 Wi-Fi）对战时**，填入 STUN / TURN：

```js
ICE_SERVERS: [
  { urls: 'stun:stun.l.google.com:19302' },
  { urls: 'turn:你的服务器:3478', username: 'user', credential: 'pass' }
]
```

> 纯 P2P 在双方都处于对称 NAT 时无法直连，此时必须借助 TURN 中继服务器。

## 浏览器兼容性

| 功能 | 要求 |
|---|---|
| 基本对局 | 任意现代浏览器 |
| WebRTC 联机 | Chrome / Edge / Firefox / Safari 均支持 |
| 邀请码压缩 | 需要 `CompressionStream`（Chrome 80+ / Edge 80+ / Safari 16.4+ / Firefox 113+），不支持时自动降级为未压缩 Base64 |

## 隐私说明

对局数据只在两台设备之间点对点传输，不经过任何服务器，也不会被上传或保存。
所有代码均在本机运行，可自行审阅 `js/` 目录下的全部源码。
