它是怎么做到的？

南孚官网首页那种"滚动时画面像视频一样前进 / 后退、松手还带惯性"的效果，其实是三套东西配合：

  • ① Canvas 序列帧：把一段动画渲染成 120 张连续图片（00000.webp ~ 00119.webp），预加载后用 drawImage() 逐张画到 canvas。
  • ② GSAP ScrollTrigger 的 scrub：把"滚动进度"映射成一个 0→119 的数字，滚到哪播到哪（可前可后）。
  • ③ Lenis：提供鼠标滚轮的惯性平滑滚动（原生滚动是一顿一顿的），这是"丝滑感"的来源。

第 1 步：预加载所有帧

const frames = [];
for (let i = 0; i < 120; i++) {
  const img = new Image();
  img.src = `/templates/assets/home/bannerFm/${String(i).padStart(5,'0')}.webp`;
  frames.push(img);
}
await Promise.all(frames.map(img => img.decode?.() || img)); // 等全部解码完成

第 2 步：Lenis 平滑滚动 + 与 GSAP 桥接（标准三件套）

const lenis = new Lenis({ duration: 1.3 });        // 惯性时长，越大越"飘"
lenis.on('scroll', ScrollTrigger.update);          // 让 GSAP 知道滚动位置
gsap.ticker.add((t) => lenis.raf(t * 1000));       // 用 GSAP 的帧循环驱动 Lenis
gsap.ticker.lagSmoothing(0);

第 3 步：scrub 把滚动进度变成帧号（精髓）

const state = { frame: 0 };
gsap.timeline({
  scrollTrigger: {
    trigger: '#scroller',
    start: 'top top',
    end: 'bottom bottom',
    scrub: 0.8,        // 0=完全跟随滚动；>0 有轻微延迟缓动，手感更顺
  },
  onUpdate() {
    drawFrame(Math.round(state.frame));   // 每一帧回调里重绘 canvas
  }
})
.fromTo(state, { frame: 0 }, { frame: 119, ease: 'none' });
// ease:'none' 很重要——帧号必须和滚动严格线性对应，否则画面会忽快忽慢

第 4 步：把对应帧画到 canvas

function drawFrame(n) {
  ctx.clearRect(0, 0, cv.width, cv.height);
  const img = frames[n];
  // cover 模式铺满画布（和 CSS object-fit:cover 同理）
  // ...计算裁切比例后 drawImage(img, sx, sy, sw, sh, 0, 0, w, h)
  ctx.drawImage(img, 0, 0);
}

为什么用图片序列，不用视频？

  • 视频只能"播放"，无法精确地和滚动条一一对应（来回拖滚动条时视频会卡顿、音画不同步）；
  • 图片序列可以随时跳到任意一帧，天然支持"滚动即进度条"，还能做透明度、位移等同步动画；
  • 代价是要预加载几十上百张图，所以站点用了 webp 压缩 + Promise.all 预载。

本 Demo 直接引用了从官网下载的真实序列帧（templates/assets/home/bannerFm/）。
真实站点的电池旋转动画(batteryFm)是 150 帧，还额外叠加了横向位移，原理相同。
